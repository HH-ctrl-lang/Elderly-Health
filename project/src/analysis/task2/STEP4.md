# 任务2 第4步：来源验证选模与东部预测轨迹

第3步发现：固定划分时，完整MLP的东部AUC在种子42/43/44分别约0.656/0.709/0.706；来源验证选择轮次分别为1/13/23。该结果提示优化与选模敏感性，但不能证明第1轮必然欠拟合，也不能证明此问题仅发生于东部。

## 本轮解决的问题

1. seed42是否在训练中产生过更好的东部排序，但原来源验证规则没有选中？曲线只作事后诊断，不按东部最佳轮次输出推荐模型。
2. 来源验证站点等权、来源地区等权、来源验证损失这些规则，是否在同一轨迹中选择了不同轮次？改变来源聚合方式是否影响东部测试表现？
3. 四个东部县区的表现是否同步变化？平均值是否掩盖站点之间相反的变化？

## 运行

更新整个实验分支后，在仓库根目录运行：

```bash
python project/src/analysis/task2/east_checkpoint_diagnostics.py
```

默认仅重训三次未加权完整MLP。固定划分、结构、损失、优化器、调度器、来源AUC早停和之前相同。需要第3步结果在默认输出目录，且使用相同Python/PyTorch/sklearn环境。可用 `--previous` 指定第3步目录。

`elderly_health/training.py`只新增可选的逐轮快照回调。脚本回调仅复制模型状态，不执行额外推理、不访问目标标签、不消耗随机数。模型训练结束后，才逐轮计算来源和东部指标；东部结果不传回优化器或选模规则。旧调用不传回调时原逻辑不变。

每个种子首先核对第3步选中轮次、东部AUC/AUPRC/Brier是否重现。未重现就停止，不带着版本或实现差异解释机制。保存的是聚合指标，不导出逐人标签、概率或模型快照。

输出：`outputs/analysis_2611/task2_step4_east_checkpoint_diagnostics/`，拒绝覆盖已有目录。

## 输出阅读顺序

- `*/reproduction_audit.json`：原模型是否重现。
- `figures/seed_*_selection_and_site_curves.png`：来源训练、来源验证、东部整体和东部四站点的轨迹；虚线是原来源验证选中轮次。
- `source_policy_comparison.csv` 与 `paired_policy_deltas.csv`：四种来源规则的选中轮次、东部评价及相对原规则的差值。
- `source_validation_site_epoch_metrics.csv`：来源各站点逐轮指标；站点少数阳性导致的估计波动可在此定位。
- `epoch_curves.csv`、`east_site_epoch_metrics.csv`：完整聚合数值。
- `experiment_metadata.json`：完成标记、版本、数据哈希和重现审计。

宏AUC要求所有相关来源组均有两类；若某个来源验证站点只有单类，则站点宏规则标记为不可用，不将它的AUC编为0.5或悄悄排除。四种规则都在原来源AUC确定的同一训练轨迹内比较，不代表它们独立训练或各自早停的完整算法效果。

若后来轮次东部变好而来源验证AUC不再变好，支持来源选模不匹配的线索；如果整个轨迹始终差，则不能仅靠更换选模轮次解释。如果规则只帮助seed42，不帮助另两次，则更可能是特定训练轨迹而不是普遍修复。即使某规则在本轮东部改善，也属于已经反复查看东部结果后的探索，需要后续来源站点交叉验证及其他地区对照。
