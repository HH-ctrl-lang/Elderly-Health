# 任务2 第5步：371082为什么持续较难预测

## 基本思路

第4步已经发现：来源验证选模解释了seed42的部分异常低表现，但371082在后续训练中仍较差。本步同时检查两件事：来源学到的特征风险顺序能否迁移到371082；MLP是否正在依赖迁移较差的信息。

例如，来源训练数据中某种手机使用类别对应较低风险，我们先冻结这套风险评分，再用于东部。如果它在110113能把阳性排在前面，到了371082却接近随机甚至反向，就得到了一条“原有关联未顺利迁移”的线索。随后打乱MLP的同一特征，观察它是否真的影响该县区的预测。这两条证据需要放在一起看。

所有19个特征都按类别编码处理，不假定教育等级等数值间距相等；缺失单列。每个特征的类别风险只由来源训练样本学习，用20个总体先验伪样本平滑稀有类别。遇到来源没有的类别，用来源总体阳性率评分，并记录未知类别比例。这个单特征模型用于诊断，不作为新预测算法或因果效应估计。

## 运行

更新当前分支后，在仓库根目录运行：

```bash
python project/src/analysis/task2/east_site_feature_transfer.py
```

使用原环境，不增加依赖。默认3次完整MLP训练，各重现原来源合并AUC选模与来源验证损失选模的两个状态。核对第4步各模型的轮次和AUC/AUPRC/Brier，通过后才分析依赖。两种选模均只用来源验证集，东部不参与训练或选择。

输出到 `outputs/analysis_2611/task2_step5_east_site_feature_transfer/`；目录已存在时拒绝覆盖。保存聚合结果，不保存逐人标签、概率或模型文件。默认县区bootstrap=300、置换=10，可用 `--bootstrap` 和 `--permutations` 增加重复次数；不要看结果后反复试参数挑最好一次。

置换在站点内进行。对同一模型及县区，各特征共用同一批行置换；手机组、社会经济组共同移动，保留组内变量关系。置换不重新训练模型。正的AUC下降表示打乱后变差，模型原先利用了这组信息；负值表示打乱后反而变好，只能称为当前模型的局部不利依赖线索。

## 解释边界

1. 单特征风险顺序不同，可能来自人群构成、其他相关因素、测量误差和抽样变化，不能直接证明条件分布变化或某个变量的因果作用。
2. 县区bootstrap按阳性/阴性分别重采样，仅反映固定来源评分下的抽样误差，不覆盖来源评分拟合误差。区间未作19项多重比较校正，不凭一个区间就宣布显著根因。
3. 置换标准差是随机打乱的数值变化，不是总体置信区间。特征间有相关性时，单独打乱可能产生不常见组合，组置换只是有限补充。不能从置换受益直接推断永久删掉该特征会改善。
4. 只有一种评分在来源和110113有用、在371082减弱，同时MLP在多个种子和两种来源选模下都依赖它，才构成较完整的机制线索；还需要来源限定的后续干预对照验证。

后续分析按“引用图片→解释横纵轴→说明真实数值→区分已知和待证”的顺序写，不把图表标题当结论。当前只交付实验代码，尚无本步真实结果。
